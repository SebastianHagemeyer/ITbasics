Pixel Painter: Pictures Are Data

Every image you have ever seen on a screen is secretly a grid of numbers. In this task you'll store a drawing as pure data, and write the code that turns it into art.

How this works: everything happens on this page. Write and run your code in the editor below, follow the steps in order, and press Submit at the bottom when you're done. Your work saves automatically as you go, and it follows you between computers. The Add to editor buttons drop example code at the bottom of whatever you've already written; merging it in (and deleting the old bits it replaces) is your job. There's always an Undo if it goes wrong. How you'll be marked is at the bottom (11 marks).
The goal: build a Picture Printer. By the end, your drawing will live in your program as pure data: a grid of letters, plus a palette that says what colour each letter means. A loop turns that data into coloured pixels. The magic test: change the data and you get completely different art without touching the loop. That's exactly how real image files work, and why one photo viewer can show every photo ever taken.

Part 0 Pictures are secretly data

        

          Zoom far enough into any photo and it falls apart into little coloured squares:
          pixels. A phone photo is about 12 million of them, and each one is
          just a colour code, the same #RRGGBB hex codes from the
          Codes & Colour lesson. A picture is nothing but a
          very long list of colour codes. Data.
        

        

          We'll paint our pixels with the block character ██ and the col=
          colour trick. The starter code in the editor prints three pixels. Run it!
        

        

          
          
        

      


      

        
Part 1 A row of pixels

        

          Printing pixels one line at a time only makes a stripe. To build a row, we need the
          pixels to sit side by side. end="" tells Python "don't jump to a new line after
          this print". Then one empty print() finishes the row.
        

        

        
Your turn: make the row longer, then shorter. Then make a second row
          in a different colour under it.

        

          
          
        

        
        
      


      

        
Part 2 The palette: letters become colours

        

          Here's the big idea of the whole task. Instead of writing the colour of every pixel by hand,
          we store the picture as a string of letters, and keep a
          palette that says what colour each letter means. The letters are the
          data. The loop is the code that reads the data.
        

        

        

          Your turn: change the row string (just the letters!) and run it
          again. Notice you're changing the picture without touching the loop. Then add a new
          letter to the palette and use it in the row.
        

        

          
          
        

      


      

        
Part 3 The whole picture: rows of data

        

          A picture is just rows stacked up, so our data becomes a list of strings,
          one string per row. To draw it we need a loop inside a loop: the outer loop
          takes each row, the inner loop takes each letter in that row.
        

        

        

          
          
        

        
        
      


      

        
Part 4 Make it YOURS (this is the goal!)

        

          Now replace the face with your own art. Design it on paper first if it helps: a grid about

Part 5 How much data is your art?

        

          Time to think like a computer. Your picture is a grid: count the rows and the columns.
          Every letter in your data is one pixel.
        

        
        
        

          A "true colour" image stores 3 bytes per pixel (one byte each for red, green and blue).
          Your program stores just one letter per pixel, three times smaller, and it only
          works because your palette has a few colours. This trick is real: it's how GIFs and old
          video games stored their graphics.
